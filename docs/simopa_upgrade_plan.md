# SimOPA 主线改进设计（v1）

## 1. 目标
- 将项目主线统一到 `SimOPA`，彻底取消 legacy 模型分支，避免结果口径混乱。
- 面向课程验收和用户体验，解决“分数差异小、解释性弱、演示不稳”三个核心问题。

## 2. 当前问题与对应方案

### P0. 主线不一致
- 问题：`simopa` 与 `legacy` 并存，评测口径混乱。
- 方案：移除 UI 和推理中的 `legacy` 入口，`infer.py` 只保留 SimOPA。
- 验收：代码中不再出现模型后端切换逻辑；默认/唯一后端为 SimOPA。

### P0. 评分有效性不稳定
- 问题：单一尺度 + 稀疏候选时，Top-K 差异不显著。
- 方案：加入多尺度联合搜索（以用户缩放为中心，尝试邻域尺度）。
- 验收：在同一图对上，Top-K 分数 gap 与 std 可观测提升。

### P1. 可解释性不足
- 问题：只给分数，不知道“为什么不合理”。
- 方案：增加规则化解释提示（边界风险、支撑关系风险、语义偏移风险）。
- 验收：每个候选至少输出 1 条可读解释。

### P1. 评测与真实需求脱节
- 问题：历史评测脚本只测 legacy 模型，不反映 SimOPA 实际表现。
- 方案：新增真实图对评测脚本，输出 Top-K 分数分布和候选细节。
- 验收：`scripts/evaluate.py --bg ... --fg ...` 可直接用于报告截图。

### P2. 离线演示鲁棒性
- 问题：权重下载失败时用户无明确修复路径。
- 方案：下载失败时给出手动放置 `SimOPA.pth` 的明确提示。
- 验收：失败信息可指导用户在 1 分钟内定位修复路径。

## 3. 实施顺序
1. 删 legacy 入口（UI + infer）  
2. 接入多尺度搜索  
3. 增加解释提示模块  
4. 重写评测脚本为 SimOPA 版  
5. 更新 README 与交付说明

## 4. 后续增强（v2）
- 增加手动位置拖动/微调评分模式。
- 增加 Grad-CAM 或遮挡实验可视化（用于进阶项“模型解释”）。
- 引入小规模真实样例集做稳定性统计（好/坏案例分层）。
